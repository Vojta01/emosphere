# EmoSphere branding pipeline (card 4/7)

How the icon, splash and PWA art are produced. Paths are relative to the repo
root. The chosen design is Vojta's variant 1, the "nebula planet"
(`/root/workspace/noc/emosphere-icons/icon_v4_nebula.svg`); a verbatim copy is
kept as `assets/branding/icon_source.svg` for provenance.

## Source of truth

`assets/branding/*.svg` are the artwork. They are generated by
`assets/branding/build_svgs.py`, which applies the four refinement rules from
the icon choice note to the picked variant:

1. **Simplified for small sizes** — one orbit ring instead of three grid
   ellipses, planet rim 3 → 9px (at 1024), dots enlarged. Legibility probes
   `emosphere_icon_preview_96.png` and `emosphere_icon_preview_48.png` are kept
   in the repo so the 48px case can be eyeballed without re-rendering.
2. **Dot hierarchy + one light direction** — dot radius encodes emotion weight
   (joy 46 → calm 34 → sad 32 → love 31 → surprise/anger 30 → fear 25 →
   tired 20) and every gradient (sphere, rim, sheen, dot highlight, dot glow)
   is lit from the upper-left, `cx`/`cy` at 27–35%.
3. **Six-colour nebula wash** — joy, love, sad, calm, anger, fear, soft
   transitions, opacity ≤ 0.30. The remaining two emotions (surprise, tired)
   appear in the dots only.
4. **Full output family** — master icon, adaptive foreground and background,
   maskable, splash hero, wordmark-free logo, splash portrait and landscape.

## Regeneration

Order matters: `flutter_launcher_icons` rewrites `web/icons`,
`web/favicon.png` and re-serialises `web/manifest.json`, so the web set is
rendered again afterwards.

```bash
cd assets/branding
python3 build_svgs.py && ./render_icons.sh   # SVG -> PNG (rsvg-convert)
cd ../..
dart run flutter_launcher_icons              # android res + web icons
dart run flutter_native_splash:create        # splash drawables + themes
cd assets/branding
./render_icons.sh && python3 verify_assets.py
```

`verify_assets.py` re-checks the safe zones and fails loudly if the art moves
outside them.

## Safe zones (verified)

| Asset | Constraint | Measured |
| --- | --- | --- |
| adaptive foreground | art inside the centre 66dp of 108dp → radius ≤ 312.9/1024 | 307.8 |
| maskable 192/512 | art inside the 80% safe circle → radius ≤ 409.6/1024 | 326.7 |
| adaptive foreground, logo, splash hero | no background, all four corners alpha 0 | OK |

The adaptive foreground carries its own inset (planet radius 295/1024), so
`adaptive_icon_foreground_inset: 0` in `pubspec.yaml` — a plugin-side inset on
top would shrink the planet to roughly 40% of the canvas.

## Outputs

- `android/app/src/main/res/mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher.png` —
  legacy launcher icon (48 … 192px).
- `android/app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` — adaptive icon:
  `@color/ic_launcher_background` (`#0B1020`) + `@drawable/ic_launcher_foreground`
  (108 … 432px, the 432px one is `drawable-xxxhdpi`).
- `android/app/src/main/res/drawable*/splash.png` + `android12splash.png` —
  pre-Android-12 and Android-12 splash art; `values-v31/styles.xml` and
  `values-night-v31/styles.xml` carry the `windowSplashScreen*` attributes.
- `web/icons/Icon-{192,512}.png`, `Icon-maskable-{192,512}.png`,
  `apple-touch-icon-180.png`, `web/favicon.png` — the PWA set.
- `web/manifest.json` and `web/index.html` — hand-written, not generated:
  name/short_name `EmoSphere`, `lang cs`, background/theme `#0B1020`, and the
  Apple status-bar/theme-color meta tags. Re-apply them if the plugin
  re-serialises the manifest.
